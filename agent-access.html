For an AI assistant or coding agent

Fetch the catalog and select items relevant to the user's question. Explain why each fits, distinguish free access from limitations, and provide the official resource links. Never imply a listed resource proves a biological hypothesis or clinical treatment.

GET https://davidwpace.github.io/open-biomedical-resource-center/data/resources.json
# Returns a static JSON object with a "resources" array.
# All filtering and scoring happen in your own client.
# No API token, user account, or patient information needed.

What works now—and what doesn't

  • Available now: Public read-only catalog, documented field names, static HTML listings, website search, links to provider documentation.
  • Not yet provided: live multi-resource search API, model inference, database proxy, hosted MCP server, Agent2Agent (A2A) endpoint, personalized biomedical recommendations or agent-run experiments.
  • Future option: A small, security-reviewed read-only MCP service could expose search_resources and get_resource, with rate limits and versioned schemas. This requires a running server or suitable worker hosting, not just static GitHub Pages.

Safety and source terms: Research and education only. No patient identifiers or private records. A link does not grant authorization to use licensed data, paid laboratory services, or clinical systems. Each upstream provider is responsible for its own claims, licensing and availability.
